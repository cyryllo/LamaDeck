# LamaDeck 1.3.1 — MCP over HTTPS, updates that really start

A small update to 1.3.0: MCP servers on the internet over HTTPS, and a fix for the old version
staying in charge after an update.

### MCP servers over HTTPS
- The address of an MCP server can start with `http://` or `https://`. On a home network
  `http://` is usually enough; for a server on the internet use `https://`.
- A certificate from a trusted authority (e.g. Let's Encrypt) works right away — also in the
  AppImage, which now uses the certificates of your system.
- If the server has its own (self-signed) certificate, choose its file in the new
  **Certificate (CA)** field of that server.
- An untrusted certificate now gives a plain message with the reason, instead of
  "the server doesn't respond".

### The new version starts after an update
- Before, when LamaDeck was still running (for example in the tray), starting the app again
  after an update only brought back the window of the **old** version.
- Now a newer version asks the running older one to close and takes its place — also when it
  is started at login.
- This works from 1.3.1 on: if 1.3.0 or older is running, close it once (tray icon → **Quit**).
- If you once installed LamaDeck with `install.sh` and now use the `.deb`, remove the old copy
  with `./install.sh --uninstall` — its menu entry may still start the old version.

### Install
- **Debian / Ubuntu**: `sudo apt install ./lamadeck_1.3.1_all.deb` — later updates come with
  `apt upgrade`.
- **Other distributions**: download `LamaDeck-1.3.1-x86_64.AppImage`, make it executable and run it.
